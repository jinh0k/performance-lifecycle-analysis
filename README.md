# 공연 수명주기 예측 (Performance Lifecycle Prediction)

> 2024 KOPIS 빅데이터 공모전 · 팀 **수명적사고** (박지현, 윤민정, 양태성, 강진호)

공연 하나를 무대에 올리면, 티켓 판매량은 시간이 지나며 오르고 내리기를 반복하다
막을 내립니다. 그 모양은 공연마다 제각각이라, 어떤 작품은 개막하자마자 확 타올랐다가
금방 식고, 어떤 작품은 입소문을 타고 뒤늦게 다시 살아납니다.

저희는 이 "판매 곡선의 모양", 즉 **공연의 수명주기**를 데이터로 유형화하고,
공연을 열기 전에 알 수 있는 정보만으로 그 유형을 미리 맞혀보려고 했습니다.
기획자가 개막 전에 "이 공연이 어떤 흐름을 탈지" 가늠할 수 있다면, 홍보 시점이나
공연 기간, 임대료 계약 같은 결정을 훨씬 덜 막막하게 내릴 수 있으니까요.

## 왜 이 주제였나

연극·뮤지컬 시장은 임대료와 제작비가 계속 오르는데 수익성은 나빠지는 상황입니다.
(연극인 가구 총수입 22.9% 감소, 뮤지컬 VIP 티켓 3년 새 27% 상승 등) 그런데
정작 공연을 얼마나 열지, 언제 마케팅에 힘을 줄지는 대부분 감과 경험으로 정해집니다.
공연을 수익성 기준으로 **도입기 → 성장기 → 성숙기 → 쇠퇴기**로 나눠서 본다면,
각 단계에 맞는 전략을 미리 세울 수 있겠다는 게 출발점이었습니다.

## 어떻게 접근했나

전체 흐름은 크게 네 덩어리입니다.

**1. 데이터 모으고 다듬기.** KOPIS 예매 데이터를 기본으로, KOSIS의 지역 인구통계와
인터파크·네이버에서 크롤링한 평점·리뷰·인지도·시놉시스를 붙였습니다. 원본은 고객
결제 단위라, 이걸 공연코드 기준으로 묶어 **작품 단위 데이터**로 바꿨습니다. 분석
범위는 문화소비가 활발한 서울·경기·경상, 2023년, 3주 이상 진행된 뮤지컬·연극으로
좁혔습니다.

**2. 시놉시스에서 주제 뽑기 (LDA).** 작품 줄거리를 KoNLPy로 토큰화하고 장르별로 LDA
토픽 모델링을 돌려, 자주 나오는 주제를 정리했습니다. 그렇게 추린 21개 키워드(사랑,
전쟁, 가족, 마법, 음악, 천재, 꿈 …)가 각 작품 줄거리에 등장하는지를 0/1로 라벨링해
"작품의 소재"를 특성으로 만들었습니다.

**3. 수명주기 유형 나누기 (군집화).** 공연마다 전체 기간을 **5개 구간**으로 쪼개고,
각 구간 판매량의 **평균·기울기·표준편차**(확산 속도·크기·일관성)를 뽑아 15개 변수를
만들었습니다. 이걸 K-Means로 묶었더니(Elbow로 k=3), 뚜렷한 세 가지 유형이 나왔습니다.

- **Peak** — 초반에 서서히 오르다 중반에 정점을 찍고 내려오는, 가장 전형적인 형태.
  주로 대학로 등 민간 공연장의 창작뮤지컬.
- **Early Peak** — 초중반에 일찍 정점을 찍고 이후 낮은 관심이 이어지는 형태.
  소극장 연극(드라마극)이 다수.
- **Retention** — 중반 정점 후 내려가다 중후반에 다시 반등(rebound)하는 형태.
  라이선스 뮤지컬·내한공연, 문화회관·국립 공연장 중심.

**4. 유형 예측하기 (분류).** 여기서 나온 군집 라벨을 정답(Y)으로 놓고, 공연 특성·주제
라벨·지역 지표를 입력(X)으로 해서 의사결정나무로 유형을 예측했습니다. 범주가 불균형해
SMOTE로 보정하고, k-fold로 과적합을 막았습니다.

## 결과

세 유형을 예측하는 분류 모델의 **F1 스코어(macro)는 0.81**이었습니다. 표본이 적은
한 유형(class 2)의 점수는 상대적으로 낮았지만 전반적으로는 잘 맞혔습니다. 유형을
가르는 데 크게 기여한 특성은 **장애인석 수·좌석 수**(공연장 규모), **공연 회차·기간**
(지속성), **배우 인지도** 순이었습니다. 공연장 규모가 수명주기 형태와 생각보다 강하게
얽혀 있다는 게 흥미로운 지점이었습니다.

이 모델을 바탕으로, 기획자가 **공연장·제목·시놉시스·대표 배우·오픈런 여부** 정도만
입력하면 수명주기 유형과 단계별(도입/성장/성숙/쇠퇴) 전략을 돌려주는 프로토타입까지
그려봤습니다. (예: '오즈의 마법사[광주]' → *Peak* 유형, 도입기 1주 / 성장기 2주 /
성숙기 2주 / 쇠퇴기 3주 이후)

## 저장소 구성

```
performance-lifecycle-analysis/
├── notebooks/        # 실제 공모전 때 돌린 분석 노트북 원본
│   ├── 전처리.ipynb
│   ├── 공연LDA.ipynb
│   ├── 군집화_학습데이터_생성.ipynb
│   └── 수명분포예측_모델링.ipynb
├── src/              # 노트북 로직을 정리한 스크립트
│   ├── preprocess.py       # 전처리
│   ├── text_features.py    # 시놉시스 주제 키워드 라벨링
│   ├── clustering.py       # 수명주기 군집화
│   └── classify.py         # 유형 예측 모델
├── requirements.txt
└── README.md
```

## 실행

```bash
pip install -r requirements.txt
python src/classify.py
```

## 데이터에 대해

분석에 쓴 데이터는 KOPIS·KOSIS 및 예매 사이트 크롤링을 결합한 것이라, **원본
데이터는 이 저장소에 올리지 않았습니다.** `src/`의 각 스크립트 docstring에 어떤
형태의 입력을 기대하는지 적어두었으니, 같은 구조의 데이터를 준비하면 그대로 돌려볼
수 있습니다.

## 남는 아쉬움

- 주제 키워드는 시놉시스의 단순 키워드 매칭이라 문맥이나 부정 표현까지는 못 잡습니다.
- 표본이 적은 유형은 예측 신뢰도가 떨어집니다.
- 특정 기간·지역·장르에 한정된 데이터라 전체 공연 시장으로 일반화하기엔 조심스럽습니다.
